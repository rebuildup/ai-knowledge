# AIエージェントの並列化は、統合と修正の時間まで測る

エージェントを同時に動かした時間だけを比較しても、並列化の効果は分からない。成果物の統合、レビュー、テスト、やり直しまで含めた**仕事の完了時間**を比べる必要がある。

## 同じファイルを編集する仕事は、並列化すると衝突しやすい

例えば「機能の実装」と「その機能のリファクタリング」を同じブランチで並行させると、一方が参照したコードをもう一方が変更してしまう可能性がある。

一方、仕様調査、実装、独立したテスト設計のように**先に成果物と変更範囲を分けられる仕事**なら、重複を抑えやすい。それでも統合後の動作確認は必要だ。

## エージェントを起動できることと、効率が上がることは違う

公開されている[dotfilesのagentランチャー](https://github.com/rebuildup/dotfiles/blob/929ec8c03e31eeb07340aa1f2b9c396a7f653a92/docs/agent-launcher.md)では、ハーネスとプロバイダを指定して実行できる。

```bash
agent list
agent claude deepseek -- -p 'say ok'
```

これは実行経路を選ぶ仕組みを示した例だ。並列化の改善率、コスト削減、完成品質の証拠ではない。

## 統合時間を含む同条件の比較がまだ必要だ

単独実行と並列実行で、同じ完了条件を使う。開始からレビュー・テスト完了までを記録し、手戻り、編集競合、API費用を別々に集計する。偶然の成功を避けるには繰り返し試行が必要になる。

| 計測値 | 除外すると分からなくなること |
| --- | --- |
| 統合までの所要時間 | 並列化で本当に早くなったか |
| レビュー・修正時間 | 人間の監督負荷が増えたか |
| 失敗・競合の件数 | タスク分割が適切だったか |
| 実際の利用料金 | 時間短縮に見合う費用か |

同条件での実験ログと試行結果はまだこの記事にない。したがって、**何倍速くなるという数値は示せない**。測定ができた段階で結果と生ログを追加する。
