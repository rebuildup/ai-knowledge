# 執筆方針

**読む人が知りたい答えを、最初の一文と見出しだけでつかめるようにする。** 文章の「AIらしさ」は、言い換えの癖だけではなく、結論が遅いこと、議題だけの見出し、内容のない説明を重ねることに現れる。

## 書き始める前に決める

読者が何を判断・実行したいのかを一文で書く。その問いへの答えを一文で書く。根拠が揃っていなければ「どこまで分かり、何が未確認か」を答えにする。

文章は **答え → 根拠 → 条件や限界 → 必要な詳細** の順で組み立てる。ただし各段落に同じ型の見出しを設けない。最初に「この記事では」「まず確認する」「〜とは何か」などの予告を置かない。

## タイトルと見出し

- タイトルは、**主題だけでなく伝えたい判断・違い・結果**を含める。検索のために必要な固有名詞は残す。
- 各見出しの下にある文章が「何を説明するか」ではなく、**何が分かるか・どうすればよいか**を表す。
- 見出しだけを縦に読んで、論点の進展が見えるか確認する。同じ主張を見出しと直後の文で二重に書かない。
- すべての見出しを断定形に揃える必要はない。事実を扱う見出し、コマンド名、UI名が自然なら使う。見出しを増やすために文章を分割しない。

| 避けたい形 | 修正する方向 |
| --- | --- |
| 「MCPとCLIの使い分け」だけで何も答えていない | 「既存のCLIで足りるならMCPは増やさない」 |
| 「何を測るべきか」 | 「並列化の評価には統合と手戻りの時間も含める」 |
| 「今後の課題」 | 「同条件の実測がないため、速度の優劣はまだ示せない」 |
| 「まず分けて考える」 | 「固定料金と上限到達後の費用を別に見積もる」 |

これは表現を機械的に変換するリストではない。根拠のない断定へ強めない。

## 語調

基本は自然な日本語の常体。必要なら敬体を使ってよいが、一記事内で立場が行き来しないようにする。流行語、煽り、「革命的」「圧倒的」など実測のない評価、過剰な強調、比喩の連続は避ける。

- 不自然な名詞の羅列を、目的に合う動詞に直す。
- 読者に不要な制作の事情・AIへの指示・Issue番号・「草稿です」を本文へ繰り返し書かない。公開状況はメタデータで管理する。
- 表・コード・本文・図の役割が重なれば、一番分かりやすい方法だけを残す。
- 個別サービスを勧めるなら、条件と比較結果を添える。確認していない料金や実績を事実として書かない。
- 公式声明と著者の見解を明確に分け、改訂日や根拠の時点を記録する。

## 文章を確定する工程

1. [writing-discipline](../.agents/skills/writing-discipline/SKILL.md)で読者・問い・答えを選ぶ。
2. [natural-japanese](../.agents/skills/natural-japanese/SKILL.md)で日本語の初稿と構成を見直す。
3. [yomiyasu](../.agents/skills/yomiyasu/SKILL.md)で意味を変えず推敲する。
4. 最後に**スキルを知らない読者の立場**で、タイトルと最初の一文、見出しだけを読み直す。何を結論として伝えたいか一目で分からなければ書き直す。

指摘数や文章の短さを品質スコアにしない。根拠と読者の理解が基準となる。
