# 図版方針

**文章を並べ直しただけの図は掲載しない。** 表にある項目を箱にして矢印でつないでも、理解が早くならなければ画像は不要だ。

## 掲載してよい図とその理由

| 素材 | 掲載する価値 | 満たす条件 |
| --- | --- | --- |
| **公式声明・仕様の抜粋** | 著者の解釈でなく原典を示せる | 元URL・発表日・対象版。引用範囲・利用条件を守る |
| **実際のスクリーンショット** | 操作位置・実際のエラー・画面差が分かる | 実機で確認し、機密や個人情報を除く。撮影時点と対象バージョンを添える |
| **構造・分岐の図** | 関係、境界、条件を本文より速く理解できる | 要素と関係が実際の仕様に対応し、正確な出典がある |
| **実測グラフ** | 複数試行や推移から傾向を読み取れる | 生データ・測定条件・単位・期間を提示 |
| **比較表・コード** | 情報を一覧・比較・コピーできる | 画像化せずテキストで載せる |

例えばMCPなら、「CLI → API」「Host → Server」と2行にする図は本文の反復に過ぎない。**1つのHostに複数Clientを作り、ClientごとにServerと1対1で接続する**関係まで描けば、文章を追うより分かりやすくなる。

## 何を削るか

- 解説文・比較表をそのまま「カード3枚＋矢印」にしたSVG。
- 情報のないロゴ・人物・AI風の装飾・アイキャッチ。
- 自動生成した架空のアプリ画面や実験のグラフ。
- 複雑な図に小さな文字を詰め込んだもの。文字量が多いなら表へ戻す。

**画像がないことは欠点ではない。価値のない画像があることは欠点になる。** 実機での証拠が必要な記事は、入手までは`draft`のまま残す。

## 制作と引用

- 公式声明は原文へのリンクと短い引用が基本。画像そのものが重要なら、ライセンスを確認して必要部分だけ使う。
- 独自図は`articles/<slug>/assets/`に編集できる元データとともに置く。意味のあるaltテキストと出典を本文に書く。
- 画像による説明と本文が完全に同じなら、どちらかを削る。
- 表示先でのスマートフォン可読性を確認する。GitHubのプレビューは本番画面の検証ではない。
- 実データ・他者の画像は出典を明示し、再利用条件に従う。公式のロゴやスクリーンショットを許諾なしに改変しない。
